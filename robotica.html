🤖¿Qué es la robótica?Semana 1

Definición

Rama de la ingeniería que se encarga del diseño, construcción y programación de robots. Combina hardware y software para crear dispositivos que realizan tareas de manera autónoma, eficiente y precisa.

Aplicaciones

  • Industria: ensamble de productos en fábricas
  • Medicina: cirugía robótica asistida
  • Exploración espacial: rovers en Marte
  • Hogar: aspiradoras, humanoides
🧩Sistema robótico: componentes

Un sistema robótico se entiende como un conjunto integrado donde interactúan tres bloques alrededor de un núcleo de control.

🧠 Controlador

Núcleo del sistema: microcontrolador (Arduino UNO) que procesa información y ejecuta el programa.

🔘 Entradas

Sensores que captan información del entorno (digital u analógica).

💡 Salidas

Actuadores que modifican el entorno: LEDs, buzzers, motores, servos.

🔋 Alimentación

Provee energía: USB (5V), pila/batería, fuente regulada.

📟Arquitectura del Arduino UNO

Microcontrolador

ATmega328P de 8 bits, 16 MHz. Es el cerebro: unidad de procesamiento + memoria + periféricos E/S.

Memoria

  • Flash: 32 KB (programa)
  • SRAM: 2 KB (variables en tiempo real)
  • EEPROM: 1 KB (datos persistentes)

Alimentación

Por USB (5V) o por jack DC (7-12V recomendado). Regulador interno baja a 5V y 3,3V.

🔘Entradas digitalesSemana 2

¿Qué es una entrada digital?

Pin configurado para leer sólo dos estados: HIGH (1, ≈5V) o LOW (0, ≈0V). Se usa para pulsadores, switches, sensores ON/OFF.

pinMode(2, INPUT); int estado = digitalRead(2); if (estado == HIGH) { /* pulsador apretado */ }
digitalRead(pin)Devuelve HIGH (1) o LOW (0)Antes: pinMode(pin, INPUT);
⚠️Un pin "al aire" (sin nada conectado) lee valores aleatorios → "flotando". Siempre usar pull-up o pull-down.
⬆️⬇️Resistencias pull-up y pull-down

🔼 Pull-UP

Resistencia entre el pin y +5V. En reposo lee HIGH. Al apretar el pulsador → cortocircuita a GND → lee LOW.

Lógica invertida: pulsado = 0, suelto = 1.

// Pull-up interno de Arduino pinMode(2, INPUT_PULLUP);

🔽 Pull-DOWN

Resistencia entre el pin y GND. En reposo lee LOW. Al apretar el pulsador → conecta a +5V → lee HIGH.

Lógica directa: pulsado = 1, suelto = 0.

// Pull-down con resistencia externa pinMode(2, INPUT); // R 10kΩ entre pin y GND
💡El valor típico de la resistencia pull-up/pull-down es 10 kΩ. Arduino tiene pull-ups internos activables con INPUT_PULLUP, así evitamos resistencia externa.
🔬¿Cómo funcionan realmente? — Esquemas interactivos

🚨 El problema: pin "flotando"

Un pin de Arduino configurado como INPUT tiene alta impedancia: casi no consume corriente. Si lo dejás suelto sin nada conectado, su lectura es impredecible: cualquier ruido eléctrico (lámparas, motores, hasta tu mano cerca) le induce una tensión variable.

Sin pull-up/down → lecturas aleatorias:
HIGH, LOW, HIGH, HIGH, LOW, HIGH... 🎲

✅ La solución

Conectamos una resistencia que "fuerce" al pin a un nivel conocido cuando el pulsador está en reposo. Y además limita la corriente cuando se aprieta el pulsador, evitando un cortocircuito entre +5V y GND.

  • Pull-UP → R va a +5V → en reposo lee HIGH
  • Pull-DOWN → R va a GND → en reposo lee LOW

🚰 Analogía del agua

Pensá el pin del Arduino como un medidor de presión. La resistencia pull-up es como una canilla de agua siempre abierta (a baja presión) — el pin "siente" presión alta (HIGH). Cuando apretás el pulsador, abrís un desagüe directo a GND: toda el agua se va al drenaje, la presión cae a cero (LOW). El pull-down es lo inverso: en reposo está conectado al drenaje (LOW), y al apretar abrís la canilla de +5V (HIGH).

📚¿Por qué SIEMPRE va la resistencia?

① Define el estado en reposo

Sin la R, el pin queda "flotando": no está conectado a nada. Cualquier interferencia eléctrica le induce una tensión y la lectura es basura.

② Evita el cortocircuito

Si conectaras +5V directo a GND al apretar el botón → cortocircuito. La R limita la corriente a I = 5V / 10kΩ = 0,5 mA: segura para el Arduino.

③ Ahorra energía

10 kΩ es un valor balanceado: lo suficientemente alto como para gastar poca corriente, y bajo como para que el ruido eléctrico no afecte la lectura.

🎁 Atajo: el Arduino tiene resistencias pull-up internas que se activan con pinMode(pin, INPUT_PULLUP). Así te ahorrás soldar la R externa y conectás el pulsador directamente entre el pin y GND. ¡La lógica sigue siendo invertida!
🔁Rebote mecánico (debounce)

El problema

Al cerrar un pulsador, los contactos metálicos rebotan durante unos pocos milisegundos, generando varias transiciones HIGH↔LOW antes de estabilizarse. El μC lee 1 pulsación como varias.

Soluciones

  • Software: delay(20-50ms) después de detectar cambio.
  • Software avanzado: usar millis() + tiempo de antirrebote.
  • Hardware: capacitor en paralelo con el pulsador (filtro RC).
// Antirrebote por software simple if (digitalRead(BTN) == LOW) { delay(30); // espera el rebote if (digitalRead(BTN) == LOW) { // confirma contador++; } }

📊Entradas analógicas — ADCSemana 3

¿Qué es el ADC?

Conversor Analógico-Digital. Toma una tensión continua (0–5V) y devuelve un número entero proporcional. El Arduino UNO tiene 6 pines analógicos (A0–A5).

Resolución del ADC

El ADC del Arduino UNO es de 10 bits: el rango 0–5V se divide en 2¹⁰ = 1024 niveles (de 0 a 1023).

Resolución = 5V / 1024 ≈ 4,88 mV
analogRead(A0)Devuelve un entero 0…1023No hace falta pinMode
V = lectura × 5 / 1023Conversión a volts
📌Cuantos más bits, mejor la resolución. 10 bits → 1024 niveles. 12 bits → 4096 niveles.

💡Salidas digitalesSemana 4

Salida digital

Un pin configurado como salida sólo puede entregar HIGH (5V) o LOW (0V). Se usa para LEDs, buzzers y otros actuadores binarios.

pinMode(13, OUTPUT); digitalWrite(13, HIGH); // enciende digitalWrite(13, LOW); // apaga
digitalWrite(pin, valor)valor = HIGH o LOWEl pin debe estar como OUTPUT
⚠️Un pin sólo puede dar hasta ~20 mA. Para encender un LED siempre hay que usar una resistencia limitadora (típica: 220 Ω).
📈PWM — Modulación por Ancho de Pulso

Concepto

El Arduino no tiene verdaderas salidas analógicas, simula valores intermedios prendiendo y apagando muy rápido el pin. La proporción del tiempo en HIGH es el ciclo activo (duty cycle).

El valor medio de la señal es proporcional al duty cycle: 50% duty → 2,5V medio. 25% → 1,25V medio.

analogWrite(pin, valor)valor = 0 (0%) … 255 (100%)Sólo pines marcados con ~

Pines PWM del Arduino UNO

~3, ~5, ~6, ~9, ~10, ~11

Frecuencia: ~490 Hz (la mayoría) y ~980 Hz (pines 5 y 6).

🎚️ Simulador PWM — moveé el duty cycle

128 / 255 (50%)

Tensión media ≈ 2.50 V

Relación clave: valor 0 → 0V, valor 128 → ~2,5V, valor 255 → 5V. Para convertir un porcentaje en valor PWM: valor = porcentaje × 255 / 100.

🤖Servomotores

¿Qué es un servo?

Dispositivo electromecánico que permite mover un eje a una cierta cantidad de grados (típicamente entre 0° y 180°). Es uno de los actuadores más importantes en robótica.

Tipos: pequeños (juguetes, robots didácticos) o industriales de mayor potencia (controlados por PLCs).

Cableado típico (3 cables)

  • ■ Rojo: +5V (alimentación)
  • ■ Marrón/negro: 0V (GND)
  • ■ Naranja/amarillo: Señal de control
📐Señal de control del servo

Señal PWM al servo

Pulsos de 5V con período de 20 a 50 ms (típico: 20 ms = 50 Hz). La duración del pulso en alto determina el ángulo:

  • 1 ms en alto → 0°
  • 1,5 ms → 90°
  • 2,5 ms en alto → 180°
// Control de servo con la biblioteca Servo #include <Servo.h> #define PIN_MOTOR 10 Servo mi_servo; // objeto de la clase Servo void setup() { mi_servo.attach(PIN_MOTOR); // asocia el pin } void loop() { mi_servo.write(0); delay(1000); mi_servo.write(45); delay(1000); mi_servo.write(90); delay(1000); mi_servo.write(135); delay(1000); mi_servo.write(180); delay(1000); }
💪TORQUE de los servomotores

¿Qué es el torque?

Es la fuerza que el eje del motor entrega para girar un sistema mecánico. Cuando usás un destornillador o pedaleás una bici, esa fuerza giratoria es torque.

El torque se obtiene multiplicando fuerza × distancia al eje.

τ = F × dTorque = Fuerza × distanciaUnidad típica en servos: kg·cm
📌El servo SG90 (el más usado en kits) tiene un torque de 1,5 kg·cm.
Ejemplo de cálculo: con un SG90 (1,5 kg·cm), si la carga está a 2 cm del eje, el peso máximo que mueve es: 1,5 / 2 = 0,75 kg = 750 g. A mayor distancia → menos peso podemos mover.
⚙️Sensores digitales ON/OFFSemana 5

Ball switch (tilt)

Sensor de inclinación. Contiene una bolita metálica que cierra el circuito cuando se inclina. Sólo dos estados: posición vertical / inclinado.

Uso: alarmas anti-vuelco, detección de movimiento brusco.

Sensor de nivel de agua

Pistas conductoras paralelas. Cuando el agua las toca, conduce y el sensor entrega señal proporcional al nivel mojado.

Lectura: analógica o como umbral digital (mojado/seco).

Sensor infrarrojo (IR)

Tipo TCRT5000: LED IR emisor + fototransistor receptor. Detecta proximidad u objetos por reflexión.

Uso: seguidor de línea, detección de obstáculos.

📡Detección de eventos

Lectura por nivel

Comparar el valor leído con un umbral. Si supera el umbral → evento (sensor activado).

if(analogRead(A0) > 500) { // agua detectada }

Lectura por flanco

Detectar el cambio de estado (LOW→HIGH o viceversa) en lugar del nivel. Útil para contar eventos sin repeticiones.

int ahora = digitalRead(SENSOR); if(ahora != anterior && ahora == HIGH){ contador++; } anterior = ahora;
📺Receptor IR y control remotoSemana 6

Receptor IR 1838B

Módulo de 3 patas (VCC, GND, OUT) que decodifica luz infrarroja modulada a 38 kHz. La salida es digital.

Control remoto 21 botones

Emite códigos infrarrojos modulados. Cada botón envía un código único (típicamente protocolo NEC).

Comunicación codificada

El emisor IR no transmite "encendido fijo" sino pulsos modulados a 38 kHz. Esto evita confundirse con la luz ambiente (filtra el ruido).

Protocolos comunes: NEC, Sony SIRC, RC5.

📚Librería IRremote.h facilita decodificar los códigos sin programar el protocolo.
// Decodificar control remoto IR #include <IRremote.h> #define RECV_PIN 7 IRrecv irrecv(RECV_PIN); decode_results results; void setup() { Serial.begin(9600); irrecv.enableIRIn(); // inicia el receptor } void loop() { if (irrecv.decode(&results)) { Serial.println(results.value, HEX); irrecv.resume(); // listo para el siguiente } }

1️⃣ Blink — el "Hola mundo" del Arduino

Semana 1
Hacer parpadear el LED interno del pin 13 cada 1 segundo.
void setup() { pinMode(13, OUTPUT); } void loop() { digitalWrite(13, HIGH); delay(1000); digitalWrite(13, LOW); delay(1000); }

Clave: pinMode en setup (una vez), digitalWrite + delay en loop.

2️⃣ Pulsador enciende LED

Semana 2
Encender un LED en el pin 9 mientras un pulsador en el pin 2 esté apretado.
#define BTN 2 #define LED 9 void setup() { pinMode(BTN, INPUT_PULLUP); pinMode(LED, OUTPUT); } void loop() { if (digitalRead(BTN) == LOW) { // pull-up → LOW = apretado digitalWrite(LED, HIGH); } else { digitalWrite(LED, LOW); } }

Clave: con INPUT_PULLUP la lógica es invertida → apretado = LOW.

3️⃣ Potenciómetro controla brillo de LED

Semanas 3 + 4
Leer un potenciómetro en A0 (0-1023) y usarlo para controlar el brillo de un LED en pin 9 vía PWM (0-255).
void setup() { pinMode(9, OUTPUT); } void loop() { int lectura = analogRead(A0); // 0..1023 int brillo = map(lectura, 0, 1023, 0, 255); analogWrite(9, brillo); // PWM }

Clave: map() escala del rango ADC (1024 niveles) al rango PWM (256 niveles).

4️⃣ Termómetro con LM35 por Serial

Semana 3
Leer el sensor LM35 en A0 y mostrar la temperatura en °C en el monitor serie cada segundo.
void setup() { Serial.begin(9600); } void loop() { int lectura = analogRead(A0); float volt = lectura * 5.0 / 1023.0; float tempC = volt / 0.01; // 10 mV/°C Serial.print("T = "); Serial.print(tempC); Serial.println(" °C"); delay(1000); }

Clave: LM35 entrega 10 mV por °C, por eso dividimos los volts por 0,01.

5️⃣ Servo de 0° a 180° y vuelta

PDF — Clase #5
Hacer girar un servomotor a las posiciones 0°, 45°, 90°, 135°, 180° con un segundo entre cada movimiento.
#include <Servo.h> #define PIN_MOTOR 10 Servo mi_servo; void setup() { mi_servo.attach(PIN_MOTOR); } void loop() { mi_servo.write(0); delay(1000); mi_servo.write(45); delay(1000); mi_servo.write(90); delay(1000); mi_servo.write(135); delay(1000); mi_servo.write(180); delay(1000); mi_servo.write(90); delay(1000); }

Clave: instanciar Servo, llamar a attach(pin) y luego write(ángulo).

6️⃣ Antirrebote con millis()

Semana 2
Contar pulsaciones de un botón sin contar rebotes, usando millis() en lugar de delay().
#define BTN 2 int contador = 0; int estado, anterior = HIGH; unsigned long ultima = 0; const unsigned long ANTIREBOTE = 50; void setup() { pinMode(BTN, INPUT_PULLUP); Serial.begin(9600); } void loop() { estado = digitalRead(BTN); if (estado != anterior && millis() - ultima > ANTIREBOTE) { if (estado == LOW) { // flanco de bajada (apretó) contador++; Serial.println(contador); } ultima = millis(); anterior = estado; } }

Clave: millis() no bloquea el programa como delay(). Se detecta el flanco de bajada (cambio HIGH→LOW).

7️⃣ Control de LED por IR remoto

Semana 6
Encender / apagar un LED con dos botones del control remoto IR.
#include <IRremote.h> #define RECV_PIN 7 #define LED 9 const long COD_ON = 0xFFA25D; // botón POWER const long COD_OFF = 0xFFE21D; // botón FUNC/STOP IRrecv irrecv(RECV_PIN); decode_results results; void setup() { pinMode(LED, OUTPUT); irrecv.enableIRIn(); } void loop() { if (irrecv.decode(&results)) { if (results.value == COD_ON) digitalWrite(LED, HIGH); if (results.value == COD_OFF) digitalWrite(LED, LOW); irrecv.resume(); } }

Clave: los códigos hex son únicos por botón. Primero hay que descubrirlos imprimiéndolos por serial.

Recordá la estructura mínima: setup() se ejecuta una sola vez al encender (acá se configuran pines y librerías) y loop() se repite para siempre. Las variables globales se declaran arriba de todo, fuera de las funciones, para que se vean desde cualquier parte.

1️⃣ Variables globales y tipos de datos

Básico
Toda variable guarda un dato. Según qué guarde, elegimos su tipo. Si la declaramos arriba de setup() es global (visible en todo el sketch).
// ───── Variables GLOBALES (se ven en setup() y loop()) ───── int contador = 0; // entero: -32768 a 32767 float temperatura = 23.5; // decimales (4 bytes) bool encendido = false; // true / false (1 bit lógico) char tecla = 'A'; // un solo carácter String mensaje = "Hola robot"; // texto void setup() { Serial.begin(9600); } void loop() { contador = contador + 1; // modifico la global Serial.print(mensaje); Serial.print(" #"); Serial.println(contador); delay(500); }

Clave: una variable global se declara afuera de las funciones y conserva su valor entre vueltas del loop(). Una local (declarada dentro de una función) nace y muere en cada llamada.

2️⃣ Declaración de pines — 3 formas

Básico
En vez de escribir números sueltos ("números mágicos"), le ponemos nombre a cada pin. Así el código se entiende y, si cambiás un cable, lo corregís en un solo lugar.
// Forma 1 — #define: lo reemplaza el preprocesador, NO usa RAM (sin ; ni tipo) #define LED_ROJO 8 // Forma 2 — const int: constante con tipo, más segura (la recomendada) const int LED_VERDE = 9; // Forma 3 — variable normal: se puede cambiar (no ideal para pines fijos) int PIN_BOTON = 2; void setup() { pinMode(LED_ROJO, OUTPUT); // salida → enciende algo pinMode(LED_VERDE, OUTPUT); pinMode(PIN_BOTON, INPUT_PULLUP); // entrada con pull-up interno } void loop() { if (digitalRead(PIN_BOTON) == LOW) { // apretado digitalWrite(LED_ROJO, HIGH); digitalWrite(LED_VERDE, LOW); } else { digitalWrite(LED_ROJO, LOW); digitalWrite(LED_VERDE, HIGH); } }

Clave: #define no ocupa memoria RAM (es un "buscar y reemplazar" antes de compilar); const int sí ocupa, pero te avisa si mezclás tipos. Ambas son mejores que dejar números sueltos.

3️⃣ Variables float y el número Pi (π)

Intermedio
Cuando un número tiene decimales usamos float. Ejemplo clásico: guardar π y calcular la circunferencia (2·π·r) y el área (π·r²) de un círculo.
// El número Pi como constante global de tipo float const float PI_VAL = 3.14159; float radio = 5.0; // cm (¡el .0 lo hace float!) float circunferencia; float area; void setup() { Serial.begin(9600); circunferencia = 2 * PI_VAL * radio; // 2·π·r area = PI_VAL * radio * radio; // π·r² Serial.print("Circunferencia: "); Serial.println(circunferencia); // 31.42 Serial.print("Area: "); Serial.println(area); // 78.54 } void loop() { }
💡
Arduino ya trae la constante PI incorporada (vale 3.1415926…), así que podrías escribir directamente 2 * PI * radio. Acá la definimos a mano para practicar los float. Recordá: un float ocupa 4 bytes y tiene ~6-7 cifras de precisión.

Clave: escribí siempre los decimales con punto (5.0, no 5,0) y agregale el .0 aunque sea redondo, para forzar que Arduino lo trate como float y no como entero.

4️⃣ Semáforo simple (3 LEDs)

Intermedio
Tres LEDs (rojo, amarillo, verde) que se encienden por turnos. Es el primer "automatismo" clásico: solo digitalWrite + delay en secuencia.
#define ROJO 8 #define AMARILLO 9 #define VERDE 10 void setup() { pinMode(ROJO, OUTPUT); pinMode(AMARILLO, OUTPUT); pinMode(VERDE, OUTPUT); } void loop() { digitalWrite(VERDE, HIGH); // 🟢 pasar delay(4000); digitalWrite(VERDE, LOW); digitalWrite(AMARILLO, HIGH); // 🟡 precaución delay(1500); digitalWrite(AMARILLO, LOW); digitalWrite(ROJO, HIGH); // 🔴 detenerse delay(4000); digitalWrite(ROJO, LOW); }

Clave: el loop() recorre verde → amarillo → rojo y vuelve a empezar. Cada delay() define cuánto dura cada luz.

5️⃣ Cruce coordinado: autos + peatones

Avanzado
Dos semáforos que trabajan juntos: cuando los autos tienen verde, el peatón ve rojo, y al revés. Usamos un for para configurar varios pines de una y otro for para hacer parpadear al peatón.
// Semáforo de AUTOS #define A_ROJO 2 #define A_AMARILLO 3 #define A_VERDE 4 // Semáforo de PEATONES #define P_ROJO 5 #define P_VERDE 6 void setup() { for (int p = 2; p <= 6; p++) { // configura pines 2..6 como salida pinMode(p, OUTPUT); } } void loop() { // 1) Autos pasan, peatón esperá digitalWrite(A_VERDE, HIGH); digitalWrite(P_ROJO, HIGH); delay(5000); digitalWrite(A_VERDE, LOW); // 2) Autos precaución digitalWrite(A_AMARILLO, HIGH); delay(2000); digitalWrite(A_AMARILLO, LOW); // 3) Autos frenan, peatón cruza digitalWrite(A_ROJO, HIGH); digitalWrite(P_ROJO, LOW); digitalWrite(P_VERDE, HIGH); delay(5000); // 4) Aviso: se acaba el tiempo (parpadea 5 veces) for (int i = 0; i < 5; i++) { digitalWrite(P_VERDE, LOW); delay(300); digitalWrite(P_VERDE, HIGH); delay(300); } digitalWrite(P_VERDE, LOW); digitalWrite(P_ROJO, HIGH); digitalWrite(A_ROJO, LOW); }

Clave: el for evita repetir 5 veces pinMode. La coordinación se logra encendiendo/apagando los pares correctos en cada etapa. ¡Nunca debe haber verde para autos y peatones a la vez!

6️⃣ Pantalla LCD 16×2 — "Hola mundo"

Avanzado
Una pantalla LCD de 16 columnas × 2 filas muestra texto. Se maneja con la librería LiquidCrystal, que viene incluida en el IDE de Arduino.
#include <LiquidCrystal.h> // LiquidCrystal(RS, E, D4, D5, D6, D7) — pines de datos LiquidCrystal lcd(12, 11, 5, 4, 3, 2); void setup() { lcd.begin(16, 2); // 16 columnas, 2 filas lcd.print("Hola Robotica!"); // escribe en fila 0 } void loop() { lcd.setCursor(0, 1); // columna 0, fila 1 (la 2da) lcd.print(millis() / 1000); // segundos encendido lcd.print(" s"); }

Clave: lcd.begin(cols, filas) inicializa; lcd.setCursor(col, fila) mueve el cursor (¡las dos empiezan en 0!); lcd.print() escribe. lcd.clear() borra todo.

7️⃣ Termómetro digital en LCD (LM35)

Avanzado
Combinamos lo aprendido: leemos el sensor de temperatura LM35 por una entrada analógica y mostramos los °C en la pantalla LCD, actualizando cada segundo.
#include <LiquidCrystal.h> LiquidCrystal lcd(12, 11, 5, 4, 3, 2); #define SENSOR A0 void setup() { lcd.begin(16, 2); lcd.print("Temperatura:"); } void loop() { int lectura = analogRead(SENSOR); // 0..1023 float volt = lectura * 5.0 / 1023.0; float tempC = volt / 0.01; // LM35: 10 mV/°C lcd.setCursor(0, 1); // fila de abajo lcd.print(tempC); lcd.print(" C "); // espacios = borran sobrante delay(1000); }

Clave: mismo cálculo del LM35 que vimos antes, pero la salida va a la lcd en vez del Serial. Los espacios al final de " C " "limpian" dígitos viejos cuando el número baja (de 25.0 a 9.0).

8️⃣ Controlar un servomotor con potenciómetro

Avanzado
Giramos el eje de un servomotor (0° a 180°) moviendo un potenciómetro. Es la base de un brazo robótico controlado a mano.
#include <Servo.h> Servo miServo; #define PIN_SERVO 9 #define POTE A0 void setup() { miServo.attach(PIN_SERVO); // asocia el servo al pin } void loop() { int lectura = analogRead(POTE); // 0..1023 int angulo = map(lectura, 0, 1023, 0, 180); miServo.write(angulo); // mueve a ese ángulo delay(15); // tiempo para llegar }

Clave: map() traduce el rango del potenciómetro (0–1023) al del servo (0–180°). El delay(15) le da tiempo físico al motor a alcanzar la posición.

9️⃣ Proyecto final: barrera de estacionamiento inteligente

Experto
El combo de todo: un botón abre/cierra una barrera (servomotor), dos LEDs indican el estado y una pantalla LCD muestra el mensaje. Además creamos nuestras propias funciones para ordenar el código.
#include <Servo.h> #include <LiquidCrystal.h> Servo barrera; LiquidCrystal lcd(12, 11, 5, 4, 3, 2); #define PIN_BARRERA 9 #define BOTON 7 #define LED_VERDE 8 #define LED_ROJO 6 bool abierta = false; // variable global: recuerda el estado void setup() { barrera.attach(PIN_BARRERA); pinMode(BOTON, INPUT_PULLUP); pinMode(LED_VERDE, OUTPUT); pinMode(LED_ROJO, OUTPUT); lcd.begin(16, 2); cerrar(); // arranca cerrada } void loop() { if (digitalRead(BOTON) == LOW) { // botón apretado if (abierta) cerrar(); else abrir(); delay(500); // antirrebote simple } } // ───── Funciones propias (organizan el código) ───── void abrir() { barrera.write(90); // levanta la barrera digitalWrite(LED_VERDE, HIGH); digitalWrite(LED_ROJO, LOW); lcd.clear(); lcd.print("PASE :) Abierta"); abierta = true; } void cerrar() { barrera.write(0); // baja la barrera digitalWrite(LED_VERDE, LOW); digitalWrite(LED_ROJO, HIGH); lcd.clear(); lcd.print("ALTO - Cerrada"); abierta = false; }
🏆
Acá juntás todo el curso: declaración de pines, una variable global bool que recuerda el estado, lectura de un botón con pull-up, control de un servo, LEDs de salida y una pantalla LCD. Las funciones abrir() y cerrar() evitan repetir código y hacen el loop() súper legible.

Clave: definir tus propias funciones (void abrir(), void cerrar()) es el gran paso de "principiante" a "ordenado". El loop() solo decide qué hacer; las funciones saben cómo hacerlo.

⚠️Errores típicos del parcial

❌ Olvidar pinMode

Sin pinMode(p, OUTPUT) en setup, el digitalWrite no funciona como esperás.

❌ Lógica de pull-up

Con INPUT_PULLUP, apretado = LOW (no HIGH). Es lógica invertida.

❌ analogWrite en pin sin ~

El PWM sólo sale por pines marcados con ~ (3, 5, 6, 9, 10, 11).

❌ Rango PWM vs ADC

ADC: 0–1023 (10 bits). PWM: 0–255 (8 bits). Usar map() para escalar.

❌ LED sin resistencia

Quema el LED o el pin. Siempre 220 Ω para LEDs comunes a 5V.

❌ delay() bloquea todo

Mientras dura, no podés leer entradas. Para multitarea: millis().
